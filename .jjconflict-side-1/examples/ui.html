A widget toolkit

Ui is ipywidgets for OCaml cells: sliders, pickers, buttons, tabs, plots, tables and timers, all running in the worker. State lives in variables; a widget on the page redraws itself whenever a variable it read changes.

open Ui let n = Var.create 42 let () = show (vbox [ int_slider ~label:"a number" ~max:100 n; dyn (fun () -> let k = Var.get n in text (Printf.sprintf "%d squared is %d, and %d is %s." k (k * k) k (if k mod 2 = 0 then "even" else "odd"))) ])

dyn makes a widget from whatever it reads, here n; nothing tells it when to redraw. The slider sets n, and the sentence follows.

Linking variables that follow each other

link keeps two variables equal; dlink makes one follow another through a function. The last two sliders are one widget shown twice.

let a = Var.create 30 let b = Var.create 70 let () = link a b let celsius = Var.create 21. let fahrenheit = Var.create 0. let () = dlink ~f:(fun c -> (c *. 9. /. 5.) +. 32.) celsius fahrenheit let twice = int_slider ~label:"shown twice" (Var.create 5) let () = show (grid ~columns:2 [ card ~title:"link" [ int_slider ~label:"a" a; int_slider ~label:"b" b ]; card ~title:"dlink" [ float_slider ~label:"°C" ~min:(-40.) ~max:100. ~step:0.5 celsius; text_of (Printf.sprintf "which is %.1f °F") fahrenheit ]; card ~title:"one widget, twice" [ twice; twice ] ])

Interact controls from a description

interact builds controls from a description written with let+ and and+ (the controls are in Interact), and redraws the widget made from their values. Here, an epidemic: the SIR model, integrated afresh as you drag.

let sir ~beta ~gamma ~days ~i0 = let dt = 0.25 in let rec go t s i r acc = if t > float days then List.rev acc else let infections = beta *. s *. i and recoveries = gamma *. i in go (t +. dt) (s -. (dt *. infections)) (i +. (dt *. (infections -. recoveries))) (r +. (dt *. recoveries)) ((t, s, i, r) :: acc) in go 0. (1. -. i0) i0 0. [] let () = show (interact ~side:true (let+ beta = Interact.float "infection rate β" ~min:0.05 ~max:1. 0.35 and+ gamma = Interact.float "recovery rate γ" ~min:0.02 ~max:0.5 0.1 and+ days = Interact.int "days" ~min:30 ~max:365 160 and+ i0 = Interact.log "first infected" ~min:(-6.) ~max:(-1.) 0.001 in let run = sir ~beta ~gamma ~days ~i0 in let series f = List.map (fun (t, s, i, r) -> (t, f s i r)) run in let peak_t, peak = List.fold_left (fun (bt, bi) (t, _, i, _) -> if i > bi then (t, i) else (bt, bi)) (0., 0.) run in let _, s_end, _, _ = List.nth run (List.length run - 1) in vbox [ Plot.( chart ~title:"Share of the population" ~x_label:"days" ~y_range:(0., 1.) ~height:320 [ area ~label:"susceptible" ~color:palette.(1) (series (fun s _ _ -> s)); area ~label:"recovered" ~color:palette.(2) (series (fun _ _ r -> r)); area ~label:"infected" ~color:palette.(4) (series (fun _ i _ -> i)); vline ~color:palette.(4) peak_t ]); hbox [ badge ~kind:(if beta /. gamma > 1. then "bad" else "good") (Printf.sprintf "R₀ = %.2f" (beta /. gamma)); badge ~kind:"warn" (Printf.sprintf "peak %.0f%% on day %.0f" (100. *. peak) peak_t); badge (Printf.sprintf "%.0f%% never infected" (100. *. s_end)) ] ]))

With ~manual:true, nothing is computed until Run is pressed: for work too slow to redo at every movement of a slider.

let sieve n = let composite = Bytes.make (n + 1) '\000' in let primes = ref [] in for i = 2 to n do if Bytes.get composite i = '\000' then begin primes := i :: !primes; (* Ints are 32 bits in the browser: i * i would overflow. *) if i <= n / i then begin let j = ref (i * i) in while !j <= n do Bytes.set composite !j '\001'; j := !j + i done end end done; List.rev !primes let () = show (interact ~manual:true (let+ n = Interact.int "primes up to" ~min:1000 ~max:2_000_000 ~step:1000 200_000 in let ps = sieve n in let rec gaps acc = function a :: (b :: _ as rest) -> gaps (float (b - a) :: acc) rest | _ -> acc in vbox [ text (Printf.sprintf "%d primes below %d; the largest is %d." (List.length ps) n (List.nth ps (List.length ps - 1))); Plot.(chart ~title:"Gaps between consecutive primes" ~height:240 ~legend:false [ histogram ~bins:30 (gaps [] ps) ]) ]))

Time, output and progress

A clock ticks while a variable says so. Each tick waits for the worker to finish the one before, so a slow tick slows the clock down rather than queueing up behind it. Handlers print to an output.

let journal = Output.create () let job = Var.create 0. let running = Var.create false let step () = let p = Var.peek job +. 0.01 in if p >= 1. then begin Var.set job 1.; Var.set running false; Output.print journal "done: 100 of 100" end else begin Var.set job p; if Random.int 8 = 0 then Output.printf journal "step %.0f: checked %d widgets" (100. *. p) (Random.int 1000) end let () = show (card ~title:"A long job" [ hbox [ button ~kind:"primary" "Start" (fun () -> Var.set job 0.; Output.clear journal; Output.print journal "starting"; Var.set running true); dyn (fun () -> if Var.get running then button "Pause" (fun () -> Var.set running false; Output.print journal "paused") else button ~disabled:(Var.get job = 0. || Var.get job >= 1.) "Resume" (fun () -> Var.set running true)) ]; progress ~kind:"good" job; output ~height:"8rem" journal; clock ~interval:50 ~running step ])

Widgets run in the worker and are drawn by the page half of x-ocaml-widgets, which patches the page in place: an input keeps its focus while the program redraws it. More things made with it: the Game of Life, the Mandelbrot set, a curve fitter, Snake.

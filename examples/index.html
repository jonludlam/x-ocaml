x-ocaml displays

Cells that draw, update what they drew, and hear back from it.

x-ocaml puts OCaml cells in a web page. Each cell's code runs in an OCaml toplevel in a Web Worker, and until now it could show only what the toplevel printed, and some fixed HTML under each phrase.

With displays, a cell can put an element on the page under itself and keep hold of it: change it later, while the cell is still running or long after, and have it call the cell back when the reader clicks it or moves a slider. An element can be plain HTML, which x-ocaml shows itself, or a custom element that a library brings with a few lines of JavaScript. Displays and callbacks belong to their cell, and go when it runs again.

It is all in X_ocaml_lib:

  • display ~tag data shows a <tag> element under the cell, update d data gives it new data, and remove d takes it away; html is a display of HTML, which needs no element of its own.
  • callback f is a token that an element can call, running f in the worker; string_of_token is what goes in its data, or in a data-callback attribute in HTML.
  • require ~tag ~src loads the script that defines an element, once.

The demos

  • Displays: a tour of what they do. An estimate of π shown as it is computed, sliders driving a plot, a canvas animated from OCaml, KaTeX, Mermaid and sound.
  • Braids: braids as words of crossings, each drawn as a picture by its printer, and Artin's test of when two words are the same braid.
  • Bach's first two-part invention: the whole piece rebuilt from its two motifs, each passage drawn as a score that plays, in an element of its own.
  • Celtic knots: knotwork drawn by following threads round a graph, with controls that redraw it and a grid whose edges you click to break the plait.
